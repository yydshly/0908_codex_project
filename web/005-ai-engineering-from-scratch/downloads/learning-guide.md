## 能力与底层机制

仓库本体由课程文档、代码、测验、学习路线与可复用产物组成。教学 Skill 使用外部 AI 宿主读取课程和进度，组织讲解、提问与复习；课程知识不会因为安装 Skill 自动变成模型权重。

RAG 的核心是文档准备、切块与索引、检索相关内容、组织上下文、生成并核验回答。Agent 的核心是目标、上下文、工具、状态、执行反馈和停止条件。生产工程把这些组件加入评估、可观测性、恢复、权限和成本约束。

代码抽查显示：Agent 入门例子使用 ToyLLM 的固定脚本模拟模型；RAG 入门示例使用 TF-IDF、简单相似度和模拟生成。它们有助于理解控制流，但不能据此推断真实模型的规划、检索或问答效果。

### 02 感知与生成

覆盖 P04、P05、P06、P08、P12。让 AI 看、听、读、创作。

关键问题：图像、声音、语言如何表示、理解和生成？不同模态怎样联系起来？

可以构建：图文理解、语音助手、内容生成。

能力边界：OCR、语音识别、语义理解和生成是不同环节；一个环节成功不代表整个任务完成。

| 技术名词 | 含义 | 用途 | 关联阶段 |
| --- | --- | --- | --- |
| CV 计算机视觉 | 从图像和视频中提取对象、结构、位置与语义。 | 看图、质量检测、视频分析。 | P04 |
| CNN 卷积神经网络 | 使用可学习的局部滤波器提取特征的网络。 | 学习图像中的边缘、纹理与对象特征。 | P04 |
| 分类 / 检测 / 分割 | 分类判断是什么，检测定位对象，分割判断像素属于哪个类别或实例。 | 有车、车在哪里、哪些像素属于车。 | P04 |
| OCR 光学字符识别 | 把图像中的字符转换为可处理的文本；版面、表格和语义理解通常还需其他步骤。 | 提取票据、截图、扫描文件中的文字。 | P04 |
| NLP 自然语言处理 | 对人类语言进行表示、分析与生成的技术领域。 | 摘要、分类、翻译、问答。 | P05 |
| Tokenization 分词与标记化 | 把文本转换为模型使用的 token 序列；token 不一定对应一个字或一个单词。 | 准备模型输入并计算上下文长度。 | P05 |

| Embedding 嵌入表示 | 把文本、图像等映射为向量，使所学习的特征可以计算和比较。 | 语义搜索、相似段落匹配、以图搜图。 | P05 |

| Diffusion 扩散模型 | 学习从带噪状态恢复数据，并通过逐步去噪等采样过程生成内容。 | 图片生成、重绘与视频生成。 | P08 |

| 跨模态对齐 / CLIP | 对齐使不同模态的相关内容在表示上建立对应；CLIP 使用对比学习联系图像与文本。 | 用文字搜索图片。 | P12 |

### 03 模型与决策

覆盖 P07、P09、P10。理解并构建模型核心。

关键问题：注意力怎样传递信息？模型怎样预测下一个 token？训练与推理有什么不同？

可以构建：小型语言模型、微调与推理实验。

能力边界：课程中的小型训练实验用于理解机制，不等于训练出具有前沿通用能力的模型。

| 技术名词 | 含义 | 用途 | 关联阶段 |
| --- | --- | --- | --- |
| Transformer | 以注意力和前馈网络等部件构成的模型架构。 | 构建语言模型，也用于图像和音频。 | P07 |
| Attention 注意力 | 比较查询与键形成分数，再加权组合值，使序列位置之间交换信息。 | 利用上下文中的相关内容；注意力分数不是可靠的推理解释。 | P07 |
| Q / K / V | Query、Key、Value，即查询、键、值，是注意力计算中承担不同角色的向量。 | 理解匹配分数怎样决定信息组合。 | P07 |
| Multi-Head Attention 多头注意力 | 在多个表示子空间分别计算注意力，再组合结果。 | 学习不同类型的上下文关联。 | P07 |
| 位置编码 / RoPE | 位置编码为序列引入位置信息；RoPE 通过旋转查询和键向量表达位置关系。 | 区分词序、利用相对距离。 | P07 |
| LLM 大语言模型 | 在大量语言相关数据上训练、通常具有较大参数规模的模型。 | 文本生成、理解、代码及工具调用决策。 | P10 |
| 自回归生成 | 根据已有序列预测后续 token，生成后再把它加入后续预测的上下文。 | 逐步生成一段回答。 | P07 |
| 预训练 / SFT | 预训练学习广泛的数据规律；SFT 是利用示范输入输出进行监督微调。 | 建立基础能力并学习遵循任务指令。 | P10 |
| Fine-tuning 微调 | 在已有模型上继续训练并调整参数，以适应任务或行为要求。 | 适应特定格式、风格和任务。 | P10 |
| LoRA / QLoRA | LoRA 训练低秩适配参数以减少可训练参数；QLoRA 配合量化基础模型降低内存需求。 | 在较有限资源下微调模型，效果仍需评估。 | P11 |
| RL 强化学习 | 通过与环境交互、接收奖励来学习行动策略。 | 连续决策、游戏、控制和奖励优化。 | P09 |
| PPO 近端策略优化 | 通过约束更新目标等方式限制策略变化的一类强化学习算法。 | 较稳定地优化行动策略。 | P09 |
| RLHF / DPO | RLHF 利用人类反馈引导训练；DPO 直接利用偏好样本优化相对输出倾向，无需经典流程中的在线 PPO 阶段。 | 让模型输出更符合偏好。 | P10 |
| MoE 混合专家 | 路由机制选择部分专家网络参与计算，模型总参数与每次激活参数可以不同。 | 扩大容量并控制每次计算开销。 | P07 |
| KV Cache | 复用已处理 token 在注意力中的键和值，减少生成时的重复计算。 | 加快生成，同时需要存储这些中间结果。 | P07 |
| 量化 Quantization | 使用较低精度表示模型权重或其他数值。 | 降低存储与内存需求，精度与速度收益需实测。 | P10 |
| 推测解码 Speculative Decoding | 由较便宜的过程提出多个候选 token，再由目标模型验证。 | 在适当条件下加速生成。 | P07 |


### 04 应用与连接

覆盖 P11、P13。接入知识、数据与外部工具。

关键问题：怎样给模型正确资料、让它使用工具，并返回可校验的结果？

可以构建：知识助手、工具集成、任务技能。

能力边界：RAG 不保证回答正确；MCP 不自动授予权限；Skill 也不等于已经执行或验证过的功能。

| 技术名词 | 含义 | 用途 | 关联阶段 |
| --- | --- | --- | --- |
| API 应用程序接口 | 软件间按约定格式请求功能和交换数据的接口。 | 调用模型、查询业务数据。 | P11 |
| Prompt Engineering 提示词工程 | 设计任务说明、示例和输出要求。 | 明确分析范围与报告格式。 | P11 |
| Context Engineering 上下文工程 | 选择、组织和更新每次调用提供的资料、历史、状态与工具信息。 | 减少遗漏、干扰和不必要的输入。 | P11 |
| Context Window 上下文窗口 | 一次调用可处理的 token 容量；输入输出限制因模型和服务而异。 | 判断长资料是否需要拆分、压缩或检索。 | P11 |
| Structured Output 结构化输出 | 让结果遵循指定数据结构，通常还需要程序侧校验。 | 把合同信息提取成固定字段。 | P11 |
| Schema 结构定义 | 描述字段名称、数据类型、必填项和约束的规则。 | 要求金额为数字、必须有来源字段。 | P13 |
| RAG 检索增强生成 | 先检索相关资料，再把资料作为上下文提供给模型生成回答。 | 知识库问答与有依据的资料总结。 | P11 |
| Chunking 文档分块 | 把长资料切成适合索引和检索的片段，并尽量保留必要语境。 | 让检索返回相关段落而不是整本手册。 | P11 |
| 向量数据库 / ANN | 向量数据库存储和检索向量；ANN 是以近似搜索换取大规模检索效率的方法。 | 在大量资料中找相似内容。 | P11 |
| Hybrid Search 混合检索 | 组合关键词与语义等不同检索信号。 | 兼顾精确型号、专有名词和近义表达。 | P11 |
| Reranking 重排序 | 对初步召回的候选结果进行更细致的相关性评分与排序。 | 把最能回答问题的资料放在前面。 | P11 |
| Tool / Function Calling 工具调用 | 模型提出工具名称和参数，由外部程序执行并返回结果。 | 计算、读取文件、查询库存。 | P13 |
| MCP 模型上下文协议 | 约定 AI 应用与工具、资源等上下文服务之间的交互方式。 | 复用统一工具连接；实现时需核对协议版本。 | P13 |
| Agent Skills 智能体技能 | 包含任务说明以及可选脚本、资源的技能包，由兼容宿主发现和使用。 | 复用资料整理、报告生成和审查方法。 | P13 |
| JSON-RPC / stdio / HTTP | JSON-RPC 描述调用消息形式；stdio 和 HTTP 是不同的通信渠道。 | 理解客户端与工具服务怎样交换请求与结果。 | P13 |
| OAuth 授权框架 | 让应用取得被许可的资源访问能力，通常通过令牌访问而非接收用户密码。 | 授权连接用户选择的数据或服务。 | P13 |


### 05 智能体与协作

覆盖 P14、P15、P16。从回答问题到执行任务。

关键问题：多步任务如何规划、恢复、分工，并用证据判断完成？

可以构建：研究助手、编程代理、自动化流程。

能力边界：自主程度和多 Agent 数量都不是质量指标；先保证单个任务可检查，再扩展持续执行和分工。

| 技术名词 | 含义 | 用途 | 关联阶段 |
| --- | --- | --- | --- |
| Agent 智能体 | 让模型围绕目标选择行动、观察结果，并在运行规则下继续执行的软件系统。 | 检索资料、生成产物并执行检查。 | P14 |
| Agent Loop 执行循环 | 决策、工具执行、记录观察、再次决策，直到满足停止条件。 | 根据查询结果决定是否继续补充资料。 | P14 |
| ReAct | 将推理与行动交替组织的一类智能体方法。 | 根据工具返回结果调整下一步。 | P14 |
| Plan-and-Execute 规划与执行 | 先拆解任务，再执行步骤，并在需要时调整计划。 | 组织竞品调研或多步骤资料处理。 | P14 |
| Workflow 工作流 | 预先规定步骤、条件与分支的流程，可以包含模型决策节点。 | 接收文件后依次提取、核验、归档。 | P14 |
| State Machine / Graph 状态机与状态图 | 通过状态、节点和转移条件组织执行路径。 | 校验失败返回修改，通过后进入交付。 | P14 |
| Agent Harness 运行支撑系统 | 管理模型周围的上下文、工具、状态、权限、预算与验证的运行环境。 | 让同一模型更可靠地完成长任务。 | P14 |
| Agent State 任务状态 | 当前运行的目标、已做操作、结果、剩余问题和预算等显式记录。 | 中断后知道做到哪里。 | P14 |
| Agent Memory 记忆 | 保存在模型之外、未来按需取用的经验、偏好或已核实信息。 | 跨任务复用项目事实，仍需可纠正和更新。 | P14 |
| Durable Execution 持久执行 | 可靠保存执行进度，使任务能够跨进程故障或中断恢复。 | 恢复长任务；还需防止重复副作用。 | P15 |
| Checkpoint / Rollback 检查点与回滚 | 检查点保存可恢复状态；回滚返回较早的可接受状态。 | 恢复进度或撤销错误修改。 | P15 |
| Multi-Agent / Orchestration 多智能体与编排 | 多个 Agent 分工，编排机制协调任务顺序、信息交换与结果汇总。 | 研究、执行和审查分工。 | P16 |
| A2A 智能体间协议 | 支持不同智能体服务发现能力、交换任务和协作的协议。 | 让不同系统中的 Agent 协作。 | P16 |
| HITL 人在回路中 | 在流程里保留人工输入、判断或批准的环节。 | 补充歧义需求和审阅重要结果。 | P15 |
| Verification Gate 验收关卡 | 根据检查与执行证据判定是否满足验收标准。 | 缺少必要检查结果时不标记完成。 | P14 |
| Scope Contract 范围契约 | 明确任务允许修改的范围、约束、输入输出与验收要求。 | 减少越界修改和目标漂移。 | P14 |
| Budget 执行预算 | 限制轮次、工具调用、时间或费用的资源边界。 | 防止无效循环与费用失控。 | P15 |


### 06 生产与交付

覆盖 P17、P18、P19。让原型可运行、可评估、可治理。

关键问题：系统上线后是否稳定、有效、成本可接受，出现问题能否定位与恢复？

可以构建：端到端 AI 产品与工程实践。

能力边界：课程覆盖生产议题不代表示例已满足生产要求；真实业务的权限、数据、性能和验收需要单独验证。

| 技术名词 | 含义 | 用途 | 关联阶段 |
| --- | --- | --- | --- |
| Inference / Serving 推理与推理服务 | 推理使用模型产生输出；服务系统负责接收、调度和持续处理请求。 | 向真实用户提供模型能力。 | P17 |
| Batching 批处理 | 合并多个请求或计算任务以提高资源利用率。 | 提高吞吐量，但需权衡排队延迟。 | P17 |
| Cache 缓存 | 保存可复用的输出或中间计算结果。 | 减少重复请求的时间与费用；需要有效性管理。 | P17 |
| Model Routing 模型路由 | 按任务要求、费用、性能与可用性选择模型。 | 为不同难度任务分配合适模型。 | P17 |
| Latency / Throughput 延迟与吞吐量 | 延迟是一次请求的等待时间；吞吐量是单位时间完成的工作量。 | 区分快速响应和承受大量并发。 | P17 |
| TTFT / TPOT | TTFT 是首次返回 token 前的等待时间；TPOT 衡量输出阶段平均每个 token 的耗时。 | 定位启动慢还是生成慢。 | P17 |
| Observability / Trace 可观测性与追踪 | 通过指标、日志与执行轨迹理解系统行为；Trace 串联一次任务的步骤。 | 定位问题发生在检索、模型还是工具。 | P17 |
| OpenTelemetry OTel | 采集、处理与传递追踪、指标、日志等遥测信息的标准与工具体系。 | 统一记录跨服务的执行过程。 | P17 |
| Eval / Benchmark 评估与基准 | 评估测量指定能力；基准使用约定任务集合进行比较。 | 比较模型、提示词和应用版本。 | P17 |
| Precision / Recall 精确率与召回率 | 精确率看找出的结果有多少相关；召回率看相关结果找到了多少。 | 分别观察误检与漏检。 | P19 |
| Faithfulness 忠实度 | 回答中的主张是否受所提供资料支持；不等于资料本身一定真实。 | 检查回答有没有添加无依据的内容。 | P19 |
| Guardrails / Sandbox 防护规则与沙箱 | 防护规则检查或约束行为；沙箱限制程序能访问和影响的环境。 | 校验输出并限制执行范围。 | P18 |
| Prompt Injection 提示注入 | 不可信输入试图改变系统原本应遵循的任务或规则。 | 识别网页或文件中误导 Agent 的指令。 | P18 |
| Red Teaming 红队测试 | 有组织地尝试使系统失败，以发现薄弱点。 | 测试错误调用、越权或信息泄漏。 | P18 |
| Alignment 对齐 | 使模型或系统行为更符合预期目标、约束和人类偏好的工作。 | 检查是否优化了表面指标却违背真实意图。 | P18 |
| Audit Log / Data Governance 审计与数据治理 | 审计记录关键行为；数据治理明确来源、权限、质量和使用规则。 | 追查行为及其数据依据。 | P18 |
| Canary / A/B Test 灰度与对照实验 | 灰度先向少量流量发布；A/B 把不同版本分配给不同组比较效果。 | 控制发布影响并衡量产品变化。 | P17 |
| Capstone 综合实践 | 组合多个模块完成端到端任务的实践项目。 | 交付有运行记录和验收结果的知识助手或 Agent。 | P19 |


## 20 个阶段的学习指引

阶段编号与课数来自目录快照。以下目标、学习时机和验收成果是我们的学习建议；正式进入课程时，还应核对该课要求。

### P00 环境与工具 12 课

主要内容：Python 环境、Git、API 密钥、Docker、GPU、调试。

学习目标：能建立可重复运行的实验环境，理解依赖、工作目录与凭据配置。

前置知识：基本电脑操作；编程基础可随课程补充。

何时学习：首次运行仓库，或出现环境、依赖、权限与调试问题。

验收成果：从明确工作目录运行一个无依赖例子，记录环境版本、命令、退出码和输出。

### P01 数学基础 22 课

主要内容：向量矩阵、微积分、概率统计、优化、信息论、数值稳定性。

学习目标：能解释模型计算和参数更新的基本数学关系。

前置知识：能阅读简单代码；P00 的环境准备。

何时学习：不理解梯度、相似度、损失函数、概率或数值问题。

验收成果：用小数组演示矩阵运算或梯度更新，并预测一次输入修改造成的变化。

[进入该阶段的固定版本课程](https://github.com/rohitg00/ai-engineering-from-scratch/tree/d18b8fe5a913c46011a3b06cb6ebd6a924414fd3/phases/01-math-foundations)

### P02 机器学习基础 18 课

主要内容：回归分类、聚类、特征工程、交叉验证、集成学习、异常检测。

学习目标：能建立数据到预测的完整基线，并区分训练效果与泛化效果。

前置知识：P01 或同等概率、代数基础。

何时学习：处理结构化数据、预测、分类或异常检测。

验收成果：在独立测试集评估一个基线，解释指标选择和错误样本。

前置知识：P01、P02 或同等知识。

何时学习：准备训练神经网络，或需要理解框架背后的运算。

## 按目标选择学习路线

不要求先学完 523 节课。先明确希望完成的任务与产物，再选择路线。以下为我们的导览建议；带专题链接的路线应优先遵循仓库清单。

### 知识助手与资料整理

适合：我们后续应用实践的默认入口。

- P00：确认环境与 API 使用

- P11：结构化输出、上下文、RAG、评估

- P05：按需补向量表示、分块和搜索

- P13：需要外部工具时学习连接

- P17 / P18：补运行、数据与权限边界

- P19：选择知识库或文档问答项目

阶段产物：能引用来源的项目资料助手。

验收重点：固定问题集、资料缺失问题、引用支持度、人工修改量、时延和单次成本。

范围取舍：暂不需要完整预训练、复杂强化学习或多 Agent。

### AI 辅助项目开发

适合：让已有编程助手更稳定地完成真实任务。

- 明确目标、任务范围与验收标准

- P14：使用仓库的 Agent-Assisted Engineering 专题

- 补仓库记忆、初始化、运行反馈与验收

- 练习隔离任务、审查和跨会话交接

- P17：按需接入项目发布与监控

阶段产物：一套适用于真实仓库的任务执行与验收说明。

验收重点：改变了哪些文件、哪些命令实际运行、结果是否对应当前版本、交接后能否恢复。

范围取舍：不用为了使用编程 Agent 先重写一个大模型。

[仓库专题清单](https://github.com/rohitg00/ai-engineering-from-scratch/blob/d18b8fe5a913c46011a3b06cb6ebd6a924414fd3/learning-paths/using-coding-agents.json)

### 产品判断与交付

适合：有想法，但还未确认应该做什么。

- P14：明确结果与真实工作流程

- 识别关键假设与最需要验证的问题

- 选最小可测试范围，写规格与成功指标

- 区分原型、试点和生产

- 建立反馈负责人和改进记录

阶段产物：一份带测试方案的项目定义与试点计划。

验收重点：谁使用、解决什么问题、成功如何测量、什么结果会改变下一步决策。

范围取舍：不要把生成了很多内容当作产生了实际收益。

[仓库专题清单](https://github.com/rohitg00/ai-engineering-from-scratch/blob/d18b8fe5a913c46011a3b06cb6ebd6a924414fd3/learning-paths/shaping-the-build.json)

### MCP 与工具连接

适合：需要连接数据源或业务工具。

- 补 P11 API 与 P13 工具契约基础

- 遵循仓库 MCP 专题清单的顺序

- 学习消息、客户端服务端、通信与上下文

- 补授权、可靠性、取消与治理

- 用真实客户端验证互通与错误行为

阶段产物：一个经过真实调用验证的工具连接。

验收重点：参数结构、拒绝无效请求、访问范围、失败恢复、协议版本和客户端兼容性。

范围取舍：专题路径不是简单按课号排序；实现前再核对当时协议规范。

### 可复用 Agent Skills

适合：希望把重复工作沉淀为可迁移方法。

- P13：Skills 契约与运行边界

- 发现与按需加载

- 调用和路由

- 权限、沙箱与信任

- 评估、打包与真实宿主验证

阶段产物：包含说明、可选脚本和资源的任务技能包。

验收重点：何时触发、不该触发时是否退出、输入输出要求、依赖、真实执行记录和卸载行为。

范围取舍：技能说明不能替代权限控制或测试；不要只验证文件存在。

### 系统理解模型原理

适合：希望逐步掌握模型内部机制。

- P00 → P01：工具与数学

- P02 → P03：机器学习与训练

- P05 → P07：语言表示与 Transformer

- P10：小模型、预训练和微调

- 按需补 P09 与 P18 的偏好和对齐

阶段产物：小型模型实验和能解释的训练记录。

验收重点：能否预测参数改变的影响、解释错误样本、区分训练损失与实际任务效果。

范围取舍：先做可运行的小实验，不以追求模型规模作为学习目标。

### 图片视频与语音应用

适合：需要处理文本之外的信息。

- 按目标选 P04 视觉、P06 音频或 P08 生成

- 按需补 P07 模型结构

- P12：融合、跨模态检索和文档理解

- P11：应用组织与评估

- P17 / P18 → P19：运行边界与综合项目

阶段产物：图文问答、语音助手或媒体处理原型。

验收重点：样本覆盖语言、噪声、分辨率和时序；分别测量识别、理解和生成环节。

范围取舍：不用同时学习所有媒体分支；先选一种输入和一种输出。

### 持续自动化与多 Agent

适合：已有稳定流程，需要持续运行或独立分工。

- P11 → P13 → P14：先建立单任务基线

- P15：持久状态、恢复、预算和回滚

- P16：按可独立任务设计分工与汇总

- P17 / P18：运行与边界评估

- P19：选择协作或自动化综合项目

阶段产物：可恢复、可追踪、有停止条件的执行系统。

验收重点：中断恢复、重复执行、协调失败、成本预算，以及相对单 Agent 的净收益。

范围取舍：避免为了展示复杂性而增加 Agent 数量。

## 每次学习如何形成证据

- 选一个具体问题：写清输入、希望得到的输出和为什么有用。

- 先讲清原理：用自己的话解释机制，并预测一个小改动的效果。

- 运行最小实现：记录环境、工作目录、命令、退出码、关键结果与产物位置。

- 改动并比较：一次只改变一个关键条件，在同一任务集上比较。

- 对照真实工具：区分模拟、真实模型调用与业务数据验证三种证据。

- 记录失败：保留错误样本、原因假设和待验证问题。

- 决定下一步：通过当前验收才扩展范围；未通过时回查相应概念。

网页中的阶段状态由你手动记录，仅保存在当前浏览器；它是学习备忘，不是系统自动认定你已经掌握。可导出 JSON 备份。阅读原理、完成练习和真实验证是不同程度。

| 状态 | 含义 | 建议证据 |
| --- | --- | --- |
| 未开始 | 尚未进入该阶段 | 无需填写 |
| 已了解 | 读过概念，知道主要问题 | 一段自己的解释 |
| 练习中 | 正在运行或改写例子 | 命令、结果和问题 |
| 已验证 | 对选定目标完成实践检查，不代表本阶段全部课程都完成 | 测试集、产物和局限说明 |


## 我们的应用场景与扩展方向

| 场景 | 学习材料 | 需要补充的工作 |
| --- | --- | --- |
| 内部知识助手 | P05、P11、P13 | 真实资料、访问权限、增量更新、引用核验 |
| 资料和文档处理 | P11、P13、P14，图像文档补 P04/P12 | 文件适配、异常处理、业务字段校验 |
| AI 辅助开发 | P14、P17 | 真实仓库测试、范围约束、版本对应的验证结果 |
| 语音或多媒体应用 | P04/P06/P08、P12 | 输入质量、模态对齐、端到端时延与失败样本 |
| 长期任务与协作 | P14、P15、P16 | 持久状态、重复执行控制、协调效果与成本比较 |


扩展顺序建议：先把一个教学示例替换为真实数据实验，再建立固定评估集；随后封装业务 Skill 和工具，加入状态与验收机制；只有单任务基线稳定且存在独立工作时，再增加多 Agent。

短期价值是降低原型试错与排错成本；中期价值是建立团队共同的输入、执行和验收标准；长期价值来自我们自己的案例、工具连接、评估集和失败修正记录。

## 容易混淆的概念

| 概念 | 关键区别 |
| --- | --- |
| 训练 / 推理 | 训练通过数据更新参数；推理使用已有参数处理输入。 |
| 提示词 / 上下文 | 提示词强调任务说明；上下文还包括资料、历史、状态与工具结果。 |
| RAG / 微调 | RAG 在回答时检索并补充资料；微调通过训练改变参数，二者可组合。 |
| 模型 / Agent | 模型产生输出；Agent 在外部软件中管理行动、工具、状态和反馈。 |
| API / MCP / Skill | API 提供功能接口；MCP 约定连接与交互；Skill 组织可复用任务说明和资源。 |
| 工作流 / Agent | 工作流可预先规定路径；Agent 可让模型参与下一步决策，也可嵌入工作流。 |
| 状态 / 记忆 | 状态记录当前运行；记忆保留可能用于后续任务的信息。 |
| 检查点 / KV Cache | 检查点用于保存可恢复进度；KV Cache 复用注意力计算中的键和值。 |
| 验收 / 授权 | 验收判断结果是否满足标准；授权判断某项行动是否允许。 |
| 相关性 / 忠实度 / 正确性 | 相关性看是否切题；忠实度看是否符合提供资料；正确性看事实是否成立。 |
| 向量检索 / 模型记忆 | 向量检索从外部索引找相似信息；不会自动将资料写进模型权重。 |
| 教学模拟 / 真实调用 | 固定脚本和模拟结果适合解释流程；需要接真实模型与数据，才能验证真实任务效果。 |


## 后期学习的最小实践建议

准备开始时，可选择“根据一组项目资料生成带出处的项目简报”。先准备少量代表性资料和固定问题；至少包含资料不足、资料冲突和需要追溯出处的情况。先手工核对标准答案或事实依据，再运行简单流程建立基线。

按步骤验证资料检索、字段提取、回答生成和引用检查，记录人工修订时间、引用支持度、成功率、时延与单次成本。若简单流程已经足够，就不增加自主循环；若失败，先根据证据定位对应模块。当前仅保留此建议，不自动启动实践。
