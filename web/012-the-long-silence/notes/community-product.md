# 从深空探索到太空社区：我们的产品理解

> 这是本研究提出的产品方向，尚未实现账号、社区或多人服务，也没有完成需求验证。原版实测画面和生成能力是技术参考；本页的关系与社区规则是我们新增的设计。

## 1. 产品的意义

**把每个人的内容、生活节奏与关系，组织成一个可以探索、可以共同建设的空间。** 太空是社区，星球是个人，航道是围绕具体内容发生的交互。用户来这里展示作品、发现同好、讨论问题、一起完成事情。

The Long Silence 的价值在于提供一套可运行的空间表达：不同外观的行星、大气、昼夜、星环、地图和探索过程。它能帮助个人主页获得记忆点，让关系和共同经历有可见的载体。但空间本身不能创造持续使用理由；产品仍要让发现内容、回复消息和参与合作足够方便。

## 2. 社区结构

| 太空元素 | 对应产品对象 | 用户能做什么 |
| --- | --- | --- |
| 宇宙 | 整个社区平台 | 搜索人、内容、活动与主题 |
| 星域／星系 | 摄影、音乐、科幻、独立开发等主题社区 | 加入主题，查看近期内容和招募 |
| 个人星球 | 个人主页与内容空间 | 发布作品、经历、需求，选择展示风格 |
| 大陆／地点 | 作品集、日志、收藏、项目分区 | 从一个作品进入具体讨论 |
| 信号 | 帖子、问题、招募或活动邀请 | 明确表达“我想分享／请教／寻找伙伴” |
| 航道 | 有上下文的会话或持续关系 | 从原始内容进入讨论，双方同意后持续交流 |
| 共同空间站 | 多人项目、活动或资源空间 | 分工、共享资料、提交成果、复盘 |
| 航行日志 | 消息、最近访问、待办与收藏 | 直接回到未完成的事，不必重复飞行 |

一个人保留一个主身份和个人星球，可通过主题标签和入口参与多个星域。主题位置不是现实地址，航道距离也不代表亲密度排名。

## 3. 不止星球：把物理外观转成可理解的产品功能

| 元素 | 表达什么 | 可操作功能与边界 |
| --- | --- | --- |
| 地貌、海洋、配色 | 长期兴趣与个人表达 | 用户自己选择；不根据外观推断人格 |
| 自转速度 | 自己选择的交流节奏 | 即时交流、每日集中回复、慢速通信；影响通知安排，不强迫限时回复 |
| 昼夜 | 当前可联系时间 | 自选时区与勿扰时段，夜间仍可留言；无需公开真实在线轨迹 |
| 大气层 | 内容开放范围 | 外层公开作品，中层主题成员，内层指定对象；逐条内容可覆盖默认值，服务端实际校验权限 |
| 天气 | 临时自述状态 | “今天想安静”“欢迎交流”等，设置有效期，到期回到中性状态 |
| 星环 | 长期兴趣与承诺 | 固定主题入口、长期计划与正在坚持的事；不作为财富或人气等级 |
| 卫星 | 独立项目 | 每颗卫星有目标、资料和进度，可邀请他人共同维护 |
| 恒星 | 一群人共同关注的目标 | 比如完成一张专辑、一次观星活动；目标不等于某个用户的地位 |
| 轨道与交会 | 双方约定的联系节奏 | 每周讨论、每月共创；用双方主动共享的时间窗口安排活动 |
| 引力 | 发出并接受邀请 | 先邀请、再确认；不暗中计算“吸引力”或默认建立私密关系 |
| 潮汐 | 自己记录的影响 | “这次交流带来的灵感”，由本人选择记录和分享 |
| 星星与星座 | 记忆和主题集合 | 保存一次交流、旅行或成果；双方各自拥有叙述和可见性选择 |
| 星云 | 未成形的想法 | 草稿、愿望、灵感池，成熟后转成信号或项目 |
| 流星与彗星 | 短期邀请与周期仪式 | 限时活动、祝福、周年提醒；明确到期和收藏规则 |

这些隐喻需要同时显示普通文字标签，例如“大气层 · 谁可以看”，让用户无需学习天文学也能理解。离线或暂停交流不会导致星球衰败，也不自动判定关系变差。

## 4. 核心使用过程

**发布作品或需求 → 合适的人发现 → 围绕内容讨论 → 双方建立航道 → 持续交流或共创 → 成果回到个人星球或共同空间。**

例子：小林在个人星球发布一组夜空照片，并发出“寻找配乐伙伴”的信号。小雨从音乐星域的跨主题内容入口看到它，围绕作品提出配乐想法。双方接受合作邀请，建立一条带有原始作品链接的航道，再创建“夜行短片”空间站。完成后，各自在个人星球展示署名成果，空间站保留过程与双方同意公开的记录。

航道应按用途组织：

- **讨论航道：**围绕一条公开内容回复；公开讨论不等于自动成为好友。
- **陪伴航道：**双方愿意保持的主题交流，例如每周交换摄影练习。
- **合作航道：**带目标、资料、分工和成果的项目会话。
- **活动航道：**围绕一次活动形成的临时群组，结束后选择归档或继续。

关系可以结束或暂停，退出、屏蔽和通知设置应直接可达；共同内容需要明确署名、访问和退出后的保留规则。

## 5. 首版做什么

首批可以邀请一个小型创作者主题群体验证，人数和主题按实际招募调整。这是待验证的切入假设。

| 页面 | 首版必须完成的事 |
| --- | --- |
| 社区星图 | 按主题发现真实内容，同时提供列表、搜索和直达链接 |
| 个人星球 | 编辑介绍、作品分区、兴趣与默认开放范围 |
| 信号详情 | 查看内容、讨论、收藏、发送有上下文的邀请 |
| 航道空间 | 接受或拒绝邀请，持续会话，查看关联作品；支持退出与屏蔽 |
| 我的导航台 | 查消息、回复待办、回到常用航道与项目 |

先实现账号、内容发布、主题发现、回复、双方接受邀请和再次访问的闭环。共同空间站的复杂分工、实时多人飞行、完整地表漫游和 AI 角色可以后置。

验收场景：两个测试账号完成上述过程；未获授权的第三个账号无法读取私密内容；拒绝或退出后不会继续收到该航道的主动邀请提醒；刷新和重新登录后内容及关系正确保留。

观察有效使用：新用户能否完成一次内容发布、信号能否带来有内容的交流、接受的航道是否在后续再次使用、是否产生共同成果。不能只用停留时长、星球数量或飞行次数判断社区价值。

## 6. 技术上怎么落地

原版可参考的部分是生成参数、行星材质、大气与昼夜表现、星图、镜头和场景资源管理。它不是现成的社交后端，多人同种子也不能替代账号、权限与动态数据同步。

建议先采用轻量星图和普通内容界面，再将可选的三维个人空间接入同一套业务数据。消息、搜索和无障碍访问不应依赖飞行或着陆完成。本次正常着陆仍有未解决的交接问题，更不宜作为首版核心流程的前置条件。

业务对象可从 User、Planet、Topic、Signal、Lane、Membership、Memory 开始；合作出现后再增加 Project、Artifact、Task。内容所有权与可见范围存于服务端，视觉层仅呈现当前用户有权看到的结果。生成种子和外观参数单独保存并带版本号，用户内容不会因渲染规则改变而丢失。

新增系统包括身份与会话、数据库和文件存储、检索、消息与通知、权限校验、举报处理和运营后台。实时编辑和多人位置同步按真实需求增加。三维场景采用按需加载、质量分档、可暂停动画和低性能设备的平面视图。

## 7. 可扩展的产品组合

| 方向 | 用户获得什么 | 在首版基础上增加什么 |
| --- | --- | --- |
| 创作者社区 | 从作品找到合作伙伴 | 作品预览、招募、合作署名、共同空间站 |
| 个人数字空间 | 具有空间表达的作品集与人生日志 | 分区编辑、可分享链接、导出与迁移 |
| 朋友／伴侣小宇宙 | 双方认可的记忆、节奏与共同计划 | 私密邀请、分别授权、纪念日与共同记录 |
| 兴趣俱乐部 | 让主题讨论和活动持续发生 | 星域管理、活动组织、成员角色与精选内容 |
| 学习与成长社区 | 展示学习成果并找到同路人 | 练习卫星、学习小组、互评和阶段成果 |
| 团队共创空间 | 以共同目标连接个人项目 | 任务、版本、资料权限与成果归档 |

后续商业化可以验证个人空间装饰、内容容量、创作工具或组织管理订阅。不出售关系强弱、曝光优越感或隐私层级；基础联系与访问控制应保持清晰一致。这些是设计选择，尚无付费意愿证据。

原库还可独立用于科幻展陈、行星参数设计器、世界观创作、分镜拍摄、图形教学与探索游戏。这些方向详见[研究说明](../README.md#可扩展方向)，不必全部塞入社区首版。
