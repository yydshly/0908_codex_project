01 · 来源资料：提供理论和经验入口关系心理学、人文社会、官方资料、社交经验四类来源。

关系科学与人格

亲密关系、依恋、Big Five、MBTI、回应性、投入与承诺；用于提出观察维度。

人文与现实背景

爱情哲学、家庭社会学、婚姻史、人口与制度变化；帮助理解价值冲突及现实约束。

官方与经验来源

法律、统计与公共卫生入口；另有沟通课程、经典社交体系和公开表达案例。来源性质不同，证据强度不能混用。

仓库怎样使用：作者在主题正文和书目中列来源，再作综合解释；库内主要是整理后的 Markdown，不是完整书籍、论文全文或原始研究数据。

后期参考价值：保留检索入口、主题词和争议点，未来定位原始研究时可以少走目录摸索的步骤。

仍缺什么：复用某条结论时仍需阅读对应原始来源，不能把“被收录”当作已独立核验。

02 · 整理与转译：把来源变成可用方法证据判断 → 主题重组 → 行为问题 → 步骤与反馈。

证据与适用范围

区分研究结论、理论框架、流行说法和经验策略；保留研究设计、适用人群与限制。

主题化与行为化

围绕关系问题组织材料，把“尊重、承诺、互惠”变成是否兑现、如何回应边界、能否修复等问题。

经验转译与维护

提取表达结构和练习，过滤操控；变更时检查链接、资料路由和边界场景。

仓库怎样使用：这些是知识治理、贡献规范与主题文档规定的编辑方法；没有采集器或清洗任务自动完成整条流程。

后期参考价值：可用于我们的领域资料模板：来源 → 主张 → 适用条件 → 行为问题 → 方法步骤 → 停止条件。

仍缺什么：逐条来源标注、审核状态和变更追踪仍需我们建设，不能直接视为现成知识生产平台。

03 · 核心知识：20 份文档的七个知识方向不仅是心理学，还包含哲学、家庭社会、制度背景和练习方法。

证据与书目 · 知识 01、19

证据分级、推理错误、概念行为化、书单与论文检索；回答“依据是什么、能判断到哪里”。

人格、依恋与关系机制 · 02、03、04

吸引、回应性、交换与投入、承诺、焦虑与回避、情绪调节、MBTI 与 Big Five；回答“有哪些可能的倾向和机制”。

关系启动与沟通 · 06、07、09

主动表达、约会、冲突与修复、线上交往、截图证据和媒介误读；回答“怎样理解当前互动”。

边界与风险 · 05、08、17

操控识别、同意、亲密边界、中国法律与危机转介入口；回答“何时停止或转向其他支持”。

哲学、婚姻与家庭社会 · 10、11、12、13、14

自由与承诺、生命周期、金钱家务育儿、双方家庭、婚姻变迁和社会结构；回答“个人选择受到哪些价值与现实条件影响”。

修复与多元关系 · 15、16

分手、背叛、复合条件；性别、性取向、异地、跨文化和其他关系形式，避免套用单一关系模板。

练习与机制拆解 · 18、20

事实拆分、价值排序、复盘与对话卡；经典社交体系的作用机制、证据和伦理转译。

仓库怎样使用：提供分析框架和提问方向；模型把这些方向与具体事件对应，不是给用户计算一个统一“人格总分”。

后期参考价值：作为个人画像说明、场景反思、沟通课程和家庭议题卡的内容基础。

仍缺什么：没有完整标准量表、常模、正式测量流程；知识 04 讨论人格，不等于提供人格测评产品。

04 · 实用方法：23 份文档怎样落实到日常表达、关系推进、职场社交、经验转译与工具使用。

日常表达

夸奖、接话、情绪支持、拒绝、化解尴尬、理性冲突、逻辑表达、引导互动与娱乐式回复。

关系推进与退出

主动表达和初次见面、现场取材与社交校准、话术编排、投入失衡；覆盖行动选择、反馈分支与退出条件。

社交与职场

请求协助、建立人脉、价值匹配与信任、被孤立时建立连接、自信与表现；在相关场景按需取用。

经典经验转译

公开表达案例、自然流与结构化互动；提炼真实表达、开放假设与反馈校准，剔除欺骗和施压。

导读与工具规则

实用 00 指导资料选择与使用分级；另有 ChatLab 适配及长期记忆说明。这三份也计入 23 份。

仓库怎样使用：把方法写成场景、步骤、表达骨架和反馈分支。话术编排器要求每轮选主策略，再按用户口吻改写。

后期参考价值：可拆成独立练习卡、回复草稿工具、沟通演练场景和复盘清单，不必整套搬入产品。

仍缺什么：话术是材料和策略示例，用户是否认可、练习是否改善行为需要产品自己的验证。

05 · 行为入口：SKILL.md 与界面元数据规定什么时候读什么资料，以及回答如何组织。

建档与目标

MBTI、用户主观评分、优势短板、关系背景、近期事件、目标和情绪；未知字段允许留空。

路由与分析规则

按回复、依恋、冲突、投入、婚姻等问题，通常选 1–3 份资料；区分事实、推测和未知。

界面入口

agents/openai.yaml 提供名称、简介与默认提示词；不代表多智能体团队或独立专业模型。

仓库怎样使用：宿主加载 Skill，模型遵循自然语言规则选择资料。此处的主观评分由用户提供，不是标准化心理测量结果。

后期参考价值：参考“场景 → 资料 → 回答结构”的组织方式，减少助手每次自由选题和无限展开。

仍缺什么：提示词是软约束；若产品要求固定计分、必要字段或禁用操作，必须另用程序落实。

06 · 大模型执行：将方法对应到具体情境情绪承接、证据拆分、权衡、建议与行动收束。

情境理解

分清目标、现实约束、人物、事件和情绪，不用类型标签补齐未知事实。

判断与建议

围绕互惠、可靠、吸引、价值观、现实可行性和机会成本权衡；选择一个主要动作。

表达与反馈

生成适合用户口吻的建议和理由，给观察窗口、停止条件及下次需要反馈的信息。

仓库怎样使用：执行者是 Codex 中的通用大模型，依据 Skill、参考文档与用户信息组织回答；仓库没有训练专用模型或独立回答审查器。

后期参考价值：可借鉴“有依据的解释 + 一个小动作 + 可观察反馈”的指导格式，用在自我反思和练习产品。

仍缺什么：资料充足不保证输出准确；引用是否忠实、推测是否冒充事实、建议是否适用，需要另作评估。

07 · 用户输入与输出：事实从哪里来用户叙述、截图、已有聊天记录 → 建议 → 用户行动与反馈。

证据识别

截图只支持可见文字、人物映射和顺序；转述需保持来源标记；线下事件要分观察、感受与解释。

反馈设计

记录是否兑现、是否明确回应、边界是否被尊重等事件，不把单条回复直接翻译为好感百分比。

仓库怎样使用：用户提供背景和后续反馈，模型给文字建议；系统不直接向对象发消息，也不替用户作现实决定。

后期参考价值：可参考事件日志字段和复盘问题，让用户修正描述、确认建议是否合适。

仍缺什么：单方叙述有信息缺口；聊天频率不等于爱意，输出完整不等于事实完整。

08 · 有限记忆：可修正的个人情境档案用户、对象、关系、事件、假设五类信息分别保存。

稳定信息与当前状态

user 保存用户偏好和目标；object 保存对象事实；relationship 保存阶段、共识与现实约束。

事件与假设

event 保存关键转折；hypothesis 保存待纠正解释。模型推断应留在假设，不能升级为稳定事实。

用户控制与程序检查

同意后启用，按对象精简召回；脚本检查来源类型和容量，支持暂停、撤销和删除。

仓库怎样使用：memory_store.py 通过 SQLite 执行有限存取；模型判断何时调用，来源类型由调用方声明，脚本不能证明内容真实。

后期参考价值：个人产品可借鉴“已知信息 / 当前目标 / 事件 / 待验证解释”分开保存，降低错误标签长期固化。

仍缺什么：不是测评历史系统、向量知识库或后台学习器；产品仍需自己的账号隔离、数据控制和测评版本记录。

服务谁：想了解自己的倾向，并获得具体改善方法的人。

用户如何使用：完成选定量表与情境自述 → 查看分维度结果 → 确认符合自己的解释 → 选择一个行动练习 → 留下实际反馈。

日常沟通练习工具

重点方向 / 个人评价 + 情境指导 + 日常练习

标准化测量、用户自述和行为练习分别显示，避免合并成没有依据的“个人总分”。上游的 MBTI 和主观综合评分是输入信息，不能替代计分引擎。

评价方向具体看什么依据性质本库能贡献什么需要补齐或避免什么
人格倾向开放性、尽责性、外向性、宜人性、负性情绪等维度候选：Big Five 体系下的具体量表；不是从聊天直接推定知识 04 帮助翻译成社交恢复、决策与计划偏好的讨论另选题目、版本、计分、中文适用证据与解释参照。
关系中的反应面对不确定、疏远或冲突时的担忧、回避与调节方式可先做情境反思；若量化依恋须另选具体量表知识 03、07 提供观察问题和调节、修复方法区分相对倾向与当前关系反应，不给永久依恋标签。
沟通与边界行为请求是否清楚、是否倾听、如何拒绝、冲突后是否修复行为清单或演练规则；不是已有标准化能力测验知识 07、08、18 与实用表达指南提供练习素材自建规则要公开其依据并验证评分一致性。
价值与生活偏好独处、计划、金钱、家庭、亲密和时间分配用户自述与排序；没有好坏总分知识 04、10、11、12 可转成偏好讨论与协商问题保留用户自己的优先级，不把不同偏好判为优劣。
