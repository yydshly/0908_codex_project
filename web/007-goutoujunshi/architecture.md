# 整体架构导读与留存结论

**结论：资料整理完成，后期按需复用；不继续深入研究、模型评测或系统接入。**

![资料整理、模型应用和可选工具的整体架构](architecture.svg)

## 怎样读图

1. **从上层看资料。** 作者按照治理与贡献规则整理不同来源，形成核心知识、实用方法和入口路由。箭头表示文档规定的编辑与组织逻辑，不能理解为自动采集清洗程序。
2. **从中层看执行。** 用户提供具体情境，Codex 中的模型读取核心规则和通常 1–3 份相关资料，完成分析并生成建议。模型的自然语言指令不是强制状态机。
3. **从下层看工具。** 记忆脚本管理有限档案，ChatLab 提供已有聊天数据的查询结果。虚线表示可选调用与返回；工具不会自动将用户内容沉淀进公开知识。

每个模块的知识方向、运行机制、参考价值与缺口，见[模块详解、后期参考价值与产品方向](modules-and-products.md)。产品部分是我们的设想，不是本库已经实现的功能。

## 各部分的职责

| 部分 | 提供什么 | 不代表什么 |
| --- | --- | --- |
| 核心知识 20 份 | 解释框架、证据限制、行为问题、书目与练习 | 完整原始文献数据库或人格测评标准 |
| 实用资料 23 份 | 策略、表达步骤、反馈分支、工具规则 | 所有经验已经过效果验证 |
| SKILL.md | 总原则、分析步骤、按主题读文件的路由 | 程序强制执行或自动审核输出 |
| Codex 中的大模型 | 理解情境、应用资料、组织回答 | 仓库训练的专用模型 |
| memory_store.py | 启用与暂停检查、来源类型限制、存取与撤销 | 来源真实性证明、人格诊断或永久标签 |
| ChatLab | 外部聊天数据查询与统计 | 仓库自带的聊天软件导出和解密能力 |

## 后期复用入口

| 以后需要什么 | 从哪里开始 |
| --- | --- |
| 了解资料整体内容 | [43 份资料汇总](materials-overview.md)、[结构化目录](materials-catalog.json) |

| 提炼沟通方法 | 实战话术编排器、冲突与修复、需求与边界主题 |
| 管理用户事实和推断 | 长期记忆说明、memory_store.py；先区分公开知识与个人档案 |

复用时从具体需求出发复核原始来源、适用范围、日期和许可，不默认复制整个资料库。
