## 当前界面与文档的差异

- 主编辑器 Save 菜单实际为 PNG / JPEG / WebP，倍率 1× / 2× / 3×，不是 README 声明的最高 5×。
- 视频弹窗实际列出 MP4 / WebM。存在动画片段后才出现 Animation / Slideshow 的类型选择。
- `lib/export/ffmpeg-encoder.ts` 和 `lib/export-slideshow-video.ts` 存在 GIF 类型与编码路径，但当前视频菜单无 GIF 按钮；没有将底层支持写成用户可直接点击。
- 当前代码页主题菜单为 Sand、Forest、Mono、Breeze、Candy、Crimson、Falcon、Meadow、Midnight、Raindrop、Sunset、Bitmap、Ice、Noir，共 14 项；README 的 32 项属于不同描述，未验证为此入口可选主题。
- “3D Objects” 面板中的素材是图像叠加，截图透视也是二维平面变换，不代表通用三维建模。

## 运行方式

在仓库根目录执行：

```powershell
./projects/011-screenshot-studio/experiments/start-original.ps1
```

启动脚本检查端口与固定提交，首次克隆并安装依赖，生成 Prisma 客户端，然后在后台启动原版，绑定 `127.0.0.1:3011`。已运行时直接返回入口，不重复启动。不会停止占用端口的其他服务，也不会覆盖不同提交的上游 checkout。

源目录：`upstream/screenshot-studio`。运行日志：`upstream/screenshot-studio-runtime`。两者由总仓库忽略。需要 Node.js、npm、Git；研究使用 Node 22.15.0，Next 16.1.6。首次页面编译实测约 88 秒，代码页首次约 8 秒，字体下载需要网络。

上游固定提交的 package-lock 缺少 `@swc/helpers@0.5.23`，`npm ci` 失败。本次 `npm install --no-audit --no-fund` 修复本地锁文件并安装 803 个包。启动脚本使用相同方式；这固定应用源码提交，不等于所有将来解析的依赖版本完全冻结。

`configure-local.mjs` 记录可重复应用的本地适配：以环境变量关闭原布局广告、Google Analytics、Databuddy 和 PostHog 初始化，新增健康接口。不修改画布、动画或导出算法。原版反馈入口仍保留，字体与外部导入仍有网络依赖。不是完全离线版。

没有配置 PostgreSQL 与 R2。新环境使用一个指向本机不可用端口的演示 DATABASE_URL，仅满足客户端生成要求；现有环境文件不会被覆盖。上游缓存操作捕获连接错误并回退，本次网址截图仍成功，但日志会记录缓存连接失败。云端缓存、清理、统计等流程未验证。
